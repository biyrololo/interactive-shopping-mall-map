# Интерактивная 2D/3D карта этажа торгового центра (Three.js WebGL)

Прототип интерактивной визуализации этажа торгового центра со 100 магазинами, динамическим построением сцены, гарантированным отсутствием пересечений, плавным переключением между 3D-перспективой и 2D-ортографическим планом, интерактивной подсветкой, поиском и архитектурой для масштабирования до 1000+ объектов.

> **Стек:** Чистый JavaScript (ES6+ Modules), Three.js, WebGL.  
> ⚠️ **Без фреймворков** (React, Vue, Angular, Svelte не используются — 100% чистый JS/DOM).

## 🕹️ Управление в приложении

- **ЛКМ (Клик по магазину):** Выбор объекта. В консоль браузера (`DevTools -> Console`) выводится подробная информация: `ID`, `Name`, `Position (x, y, z)`, габариты, категория. На сцене магазин фиксируется неоновой подсветкой и открывается карточка объекта.
- **Пробел (Space) или кнопка «2D/3D»:** Плавное переключение между 3D-перспективным видом и 2D-планом сверху.
- **Вращение / Панорама:** 
  - В 3D-режиме: зажатая ЛКМ вращает сцену, ПКМ панорамирует, колесико мыши зумирует.
  - В 2D-режиме: вращение блокируется строго под прямым углом, доступны панорамирование и зум.
- **Клавиша `F` (или кнопка в карточке):** Плавный перелет камеры к выбранному объекту.
- **Клавиша `Esc` (или клик по пустому полу):** Сброс выделения.
- **Поиск в шапке:** Мгновенный поиск по названию или ID с автодополнением и перелетом камеры к объекту.
- **Селектор подписей:** Переключение способов отрисовки текста (`CSS2D Бейджи`, `Текстуры на крыше`, `WebGL Спрайты`, `Все вместе`).
- **Кнопка «ℹ️ Архитектура & ТЗ»:** Открытие встроенного модального окна с ответами на теоретические вопросы ТЗ.

## 📐 Алгоритм размещения 100 объектов без пересечений

### Выбранный подход: «Архитектурный галерейный упаковщик (Dual-Aisle Mall Gallery Packer)»

Вместо случайного разбрасывания или абстрактной одномерной упаковки, выбран алгоритм, моделирующий реальное устройство современных торговых центров:

1. **Галерейная блочная структура:**
   - 100 магазинов группируются в торговые ряды вдоль пешеходных проспектов (ширина прохода `AISLE_WIDTH = 4.0` м).
   - Магазины размещаются по парам рядов:
     - С тыльной стороны магазины стоят «спина к спине» с технологическим зазором `SHOP_PADDING = 0.6` м.
     - Фасадная часть магазинов выходит на широкий пешеходный коридор.
   - Поперек торгового центра проходит центральный бульвар (`CROSS_AISLE_WIDTH = 5.0` м), делящий этаж на Западное и Восточное крыло.

2. **Математическая гарантия отсутствия коллизий:**
   - Каждый магазин имеет габариты `width` и `depth` (от 3.0 до 8.0 метров).
   - По оси X магазины выстраиваются последовательно с гарантированным отступом:  
     $$X_{i+1} = X_i + \frac{W_i}{2} + \text{Padding} + \frac{W_{i+1}}{2}$$
   - По оси Z переход на следующий ряд учитывает максимальную глубину предыдущего ряда:  
     $$Z_{\text{next}} = Z_{\text{curr}} + \max(\text{depth}_{\text{row}}) + \text{AisleGap}$$
   - После раскладки весь торговый центр центрируется относительно точки `(0, 0, 0)`.

3. **Автоматическая верификация пересечений (AABB Collision Test):**
   - В модуле `src/layout/packer.js` и в тесте `test/layout.test.js` встроен алгоритм попарной проверки пересечений 2D Axis-Aligned Bounding Box:
     $$\text{Overlap} \iff (|x_A - x_B| < \frac{w_A + w_B}{2} - \varepsilon) \land (|z_A - z_B| < \frac{d_A + d_B}{2} - \varepsilon)$$
   - При запуске тест проверяет все $\frac{100 \times 99}{2} = 4950$ пар. Результат: **0 пересечений**.

## 🔄 Реализация переключения 2D/3D (Плюсы и минусы подходов)

В проекте реализовано переключение между:
- **3D-режимом:** Перспективная камера (`PerspectiveCamera`, угол обзора $48^\circ$, наклонный ракурс, полноценный объем объектов с высотой $H = 2.0$, мягкие тени).
- **2D-режимом:** Ортографическая камера (`OrthographicCamera`, строгий вид сверху $90^\circ$, отсутствие перспективных искажений, одинаковый масштаб чертежа в любой точке экрана).

### Как устроена плавная анимация:
1. При нажатии клавиши `Пробел` или клике по кнопке запускается интерполяция длительностью $1.1$ секунды на базе кубической кривой сглаживания `easeInOutCubic`.
2. Координаты камеры и точка фокуса `controls.target` плавно перемещаются между наклонной позицией и зенитом строго над сценой.
3. Одновременно анимируется высота самих 3D-параллелепипедов через масштаб `scale.y` и позицию `position.y`:
   - В 2D высота сжимается до $0.08$ м («прижимается к полу»), превращая здания в плоский архитектурный чертеж этажа.
   - В 3D высота плавно вырастает обратно до $2.0$ м.
4. В наивысшей точке перехода происходит бесшовное переключение проекции между `PerspectiveCamera` и `OrthographicCamera` с согласованными границами Frustum, исключая скачки изображения.

### Сравнение подходов (Плюсы и минусы):

| Подход | Плюсы | Минусы |
|---|---|---|
| **А. Две камеры (Perspective + Orthographic) с анимацией перелета (выбрано)** | • Честная 2D-ортогональная проекция без параллакса по краям экрана.<br>• Легко зафиксировать вращение в 2D, превратив карту в классический чертеж плана.<br>• В 3D сохраняется естественная глубина и реалистичные тени. | • Требуется синхронизация размеров Frustum ортографической камеры и угла обзора перспективной камеры. |
| **Б. Только перспективная камера (просто поворот камеры на $90^\circ$ вниз)** | • Реализуется буквально в пару строк кода.<br>• Не нужно переключать инстансы камер. | • Не является истинным 2D: по краям экрана виден параллакс и боковые грани стен (эффект «рыбьего глаза» при широком FOV). |
| **В. Морфинг проекционной матрицы (FOV $\to 0$, Distance $\to \infty$)** | • Непрерывное математическое преобразование. | • При FOV близком к 0 возникают артефакты Z-fighting и числовая нестабильность матрицы проекции в WebGL. |

## 🏷️ Обработка текстовых подписей и граничные случаи

### Реализованные способы отображения подписей:
1. **CSS2DRenderer (HTML Billboarding Badges):**
   - Интерактивные DOM-бейджи поверх WebGL канваса.
   - Идеально четкий векторный рендеринг шрифтов на экранах любой плотности (Retina/4K).
   - Поддерживают CSS-анимации, тени, hover-состояния.
2. **Текстуры на крыше (Roof Canvas Textures):**
   - Запекаются в динамический `THREE.CanvasTexture` высокого разрешения.
   - Лежат непосредственно на плоскости крыши магазинов. В 2D-режиме превращают сцену в фотореалистичный план здания.
3. **WebGL Canvas Sprites (Billboarding):**
   - Векторные трехмерные спрайты, всегда смотрящие на камеру средствами WebGL.

### Граничные случаи: Длинные названия магазинов
В датасете специально предусмотрены стресс-тесты с очень длинными названиями (например, *«Флагманский гипермаркет электроники и бытовой техники «М.Видео-Эльдорадо»»*, *«The Body Shop — 100% Vegetarian & Cruelty-Free British Cosmetics»*):
- **В CSS2D:** Использовано CSS-правило `text-overflow: ellipsis`, предотвращающее расползание интерфейса. Полное название доступно в атрибуте `title` при наведении и отображается в карточке выбранного магазина.
- **В Canvas-текстурах:** Реализован алгоритм бинарного поиска допустимой длины строки (`CanvasTextGenerator.truncateText`), измеряющий текст через `ctx.measureText` с учетом масштаба помещения и добавляющий `...` ровно в границах стен магазина.

## 🧠 Архитектура и оптимизация (Обязательный блок 4)

### Вопрос 1: Как оптимизировать рендеринг текстовых подписей при 1000+ объектах?

При переходе от 100 к 1000+ текстурированным объектам использование 1000 отдельных DOM-элементов (`CSS2D`) приведет к просадке FPS из-за нагрузки на подсистему композитинга и перерасчета геометрии страницы браузером (Reflow & Layout Thrashing). 

**Комплекс решений для 60 FPS:**
1. **SDF (Signed Distance Field) / MSDF Font Texture Atlas:**
   - Все глифы алфавита запекаются в одну компактную текстуру (2048×2048).
   - Все 1000 подписей рендерятся как квады геометрии через один общий `InstancedMesh` или `BatchedMesh`.
   - **Результат:** Вместо 1000 DOM-узлов или 1000 вызовов отрисовки — **ровно 1 Draw Call** на GPU с идеальной резкостью при любом зуме.
2. **Frustum & Distance Culling (Отсечение невидимого):**
   - На уровне JS на каждом кадре отсекаются объекты вне видимой пирамиды камеры (`cameraViewFrustum.intersectsBox(shop.box)`).
   - Подписи магазинов дальше определенного расстояния $R_{\max}$ отключаются.
3. **LOD (Level of Detail) & Decluttering (Генерализация карты):**
   - При общем плане (зум отдален) отображаются подписи только якорных арендаторов (Фуд-корт, Супермаркет).
   - Подписи небольших магазинов и бутиков плавно проявляются через альфа-канал только при приближении камеры.
4. **Коллизии надписей на экране (Screen-space Occlusion):**
   - Использование пространственного дерева (R-tree) в координатах экрана: если подписи перекрывают друг друга, отображается только приоритетная.

### Вопрос 2: Как обрабатывать клики по объектам при объединении геометрии (InstancedMesh / Merged Geometry)?

При объединении 1000 объектов в один `THREE.InstancedMesh` сцена рисуется за один вызов, но традиционный Raycaster по отдельным `THREE.Mesh` больше неприменим.

**Три эффективных решения:**

1. **Штатный Raycasting по `THREE.InstancedMesh` (Рекомендуемый для Three.js):**
   ```javascript
   const intersects = raycaster.intersectObject(instancedMesh);
   if (intersects.length > 0) {
     const instanceId = intersects[0].instanceId; // Уникальный индекс инстанса!
     const shopData = placesData[instanceId];     // O(1) доступ к объекту
     console.log("Выбран магазин:", shopData);
   }
   ```
   Three.js умеет вычислять пересечение луча с конкретной матрицей инстанса и возвращает `instanceId`. Доступ к данным занимает $O(1)$.

2. **GPU Color Picking (Offscreen Framebuffer Picking):**
   - Сцена рендерится в скрытый внеэкранный буфер (`WebGLRenderTarget`) размером 1×1 пиксель прямо под курсором мыши с кастомным шейдером, где цвет каждого объекта кодирует его уникальный ID:
     $$\text{ID} \to (R, G, B) \quad (R = \text{ID} \& 255, \; G = (\text{ID} \gg 8) \& 255, \; B = (\text{ID} \gg 16) \& 255)$$
   - Метод `gl.readPixels(x, y, 1, 1, gl.RGBA, ...)` считывает 1 пиксель и раскодирует ID обратно.
   - **Плюсы:** Работает с абсолютно любой геометрией (Merged, Skinned, Instanced, Particle) со сложностью $O(1)$ вне зависимости от числа полигонов (хоть 1,000, хоть 10,000,000 полигонов).

3. **BVH (Bounding Volume Hierarchy via `three-mesh-bvh`):**
   - Для объединенных мешей строит иерархическое дерево ограничивающих объемов (AABB).
   - Raycasting ускоряется с $O(N)$ до $O(\log N)$, отсекая 99% геометрии на первых этапах теста.

### Вопрос 3: Структура хранения данных в JS для мгновенного поиска по ID и координатам

В проекте эта архитектура не просто описана, а **полностью реализована** в модуле `src/data/spatialIndex.js`:

```
                    ┌─────────────────────────┐
                    │    placesData (Array)   │
                    └────────────┬────────────┘
                                 │
             ┌───────────────────┴───────────────────┐
             ▼                                       ▼
  ┌───────────────────────┐             ┌─────────────────────────┐
  │ Map<string, PlaceData>│             │   2D Spatial Hash Grid  │
  ├───────────────────────┤             ├─────────────────────────┤
  │ ID: 'shop_001' ───► {}│             │ "cx:cz" ──► Set<Shop>   │
  │ ID: 'shop_002' ───► {}│             │ "1:3"   ──► {A, B}      │
  │ Сложность: O(1)       │             │ Сложность: O(1) avg     │
  └───────────────────────┘             └─────────────────────────┘
```

1. **Поиск по ID: `Map<string, PlacedShop>`**
   - В JS встроенная структура `Map` использует эффективную хэш-таблицу.
   - `spatialIndex.getById('shop_001')` возвращает ссылку на объект за **$O(1)$**.

2. **Поиск по координатам $(x, z)$: `2D Spatial Hash Grid`**
   - Плоскость этажа разбивается на регулярную сетку ячеек размером `cellSize` (например, 8 метров).
   - Ключ ячейки вычисляется математически за $O(1)$:
     ```javascript
     const cellKey = `${Math.floor(x / cellSize)}:${Math.floor(z / cellSize)}`;
     ```
   - Каждый объект регистрируется только в тех ячейках, которые пересекает его AABB.
   - При клике или проверке координат $(x, z)$ мы берем бакет по ключу `cellKey` и тестируем AABB только 1–3 кандидатов, находящихся в этой точке, без обхода всех 1000 элементов.
   - **Сложность:** **$O(1)$** в среднем.

3. **Альтернатива для неравномерных плотностей: 2D Quadtree / R-Tree (`RBush`)**
   - При сильном перепаде размеров (огромный гипермаркет 80×50 м и микроостровки 2×2 м) квадродерево или R-дерево делит плоскость адаптивно.
   - Обеспечивает диапазонные выборки (Range Query) «найти все магазины в видимой области экрана» за **$O(\log N + K)$**.
