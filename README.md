# Интерактивная 2D/3D карта этажа торгового центра (Three.js WebGL)

Легковесный, высокопроизводительный прототип интерактивной карты этажа торгового центра на 100 магазинов.

> **Стек:** Чистый JavaScript (ES6+ модули), Three.js, WebGL, Vite.  
> ⚠️ **Без фреймворков** (React, Vue, Angular, Svelte исключены в соответствии с ТЗ).

---

## ⚡ Оптимизация и производительность

В проекте намеренно исключены избыточные абстракции и ресурсоемкие эффекты, вызывавшие просадки FPS:
1. **Текстовые подписи через `THREE.Sprite` (Чистый WebGL):**
   - Вместо 100 тяжелых DOM-элементов (`CSS2DRenderer`), которые перегружали композитор браузера пересчетом `transform3d` и вызывали лаги, используются нативные спрайты Three.js.
   - Каждый спрайт использует компактный canvas 256×64 px.
   - Отрисовка происходит на 100% силами GPU в общем рендер-пассе.
   - Автоматический **billboarding** (спрайт всегда ориентирован на камеру).
2. **Оптимизированный Raycasting:**
   - Raycaster не вызывается на каждое микро-движение мыши в событии `pointermove`.
   - Проверка пересечений выполняется по флагу `mouseMoved` **внутри цикла `requestAnimationFrame` не чаще одного раза за кадр** (максимум 60 раз/сек вместо 500+ раз/сек).
   - Луч тестируется только по массиву из 100 мешей магазинов, а не по всей сцене.
3. **Легковесные материалы и освещение:**
   - Использованы стандартные материалы с мягким направленным и рассеянным светом без тяжелых 2048-пиксельных карт теней.
4. **Результат:** стабильные **60+ FPS** и минимальное потребление оперативной памяти.

## 🎮 Управление

- **ЛКМ (Клик по магазину):** Выбор магазина.
  - В консоль браузера (`DevTools -> Console`) выводится: `ID`, `Name`, `Position (x, y, z)`.
  - Магазин подсвечивается неоновым бирюзовым цветом, в левом нижнем углу открывается карточка.
- **Пробел (Space) или кнопка «2D/3D»:** Плавное переключение между 3D-видом и 2D-планом сверху.
- **Вращение / Панорамирование / Зум:**
  - В 3D: зажатая ЛКМ вращает камеру, ПКМ панорамирует, колесо мыши зумирует.
  - В 2D: вращение заблокировано строго сверху, доступны панорамирование и зум.
- **Поиск в шапке:** Быстрая фильтрация по названию/ID с фокусировкой камеры на найденном объекте.
- **Esc:** Сброс выделения.

## 📐 Алгоритм размещения 100 объектов без пересечений

**Подход:** «Ряды торговых галерей с динамическим шагом» (см. [`src/layout.js`](file:///Users/biyrololo/Projects/my_projects/webgl-interactive-map/src/layout.js)):

1. 100 магазинов упорядочиваются по рядам (по 10 магазинов в ряду, 10 рядов).
2. По оси X магазины следуют последовательно:  
   $X_{i+1} = X_i + \frac{W_i}{2} + \text{gapX} + \frac{W_{i+1}}{2}$, где $\text{gapX} = 1.2$ м.
3. По оси Z каждый ряд отделен пешеходным проходом $\text{aisleGap} = 3.5$ м, рассчитанным от максимальной глубины магазинов текущего ряда:  
   $Z_{\text{row}+1} = Z_{\text{row}} + \max(\text{depth}_{\text{row}}) + \text{aisleGap}$.
4. После размещения координаты центрируются относительно точки $(0, 0, 0)$.
5. **Математическая гарантия отсутствия коллизий:**
   Функция `checkCollisions` попарно сравнивает 2D AABB всех объектов:
   $$\text{Overlap} \iff (|x_A - x_B| < \frac{w_A + w_B}{2} - \varepsilon) \land (|z_A - z_B| < \frac{d_A + d_B}{2} - \varepsilon)$$
   Результат: **0 пересечений** (подтверждается автоматическим тестом `npm test`).

## 🔄 Переключение 2D / 3D: Плюсы и минусы

В проекте используется связка из **двух камер**:
- `PerspectiveCamera` (3D): камера под углом $45^\circ$, магазины объемные (высота $2.0$ м).
- `OrthographicCamera` (2D): вид строго сверху $90^\circ$, магазины плавно сжимаются до пола (высота $0.08$ м), блокируется вращение.
- При нажатии клавиши `Пробел` в течение 0.8 сек интерполируются позиция камеры, целевая точка и масштаб коробок по высоте (`scale.y`).

### Плюсы и минусы подходов:
- **Две камеры (Perspective + Orthographic) — [Выбрано]:**
  - *Плюсы:* В 2D получается честный архитектурный план этажа без искажений масштаба по краям экрана. В 3D — полноценная глубина и перспектива.
  - *Минусы:* Требуется синхронизация Frustum ортографической камеры с Aspect Ratio окна.
- **Одна перспективная камера (просто поворот камеры вниз):**
  - *Плюсы:* Код проще на несколько строк.
  - *Минусы:* Это не настоящий 2D-план — из-за угла обзора (FOV) по краям экрана виден параллакс и боковые грани стен.

## 🧠 Архитектура и оптимизация (Раздел 4 ТЗ)

### 1. Оптимизация текстовых подписей при 1000+ текстурированных объектах
- **SDF (Signed Distance Field) / MSDF Font Atlas:** Вместо генерации отдельных текстур шрифты запекаются в единый атлас. Все 1000 подписей отрисовываются как квады через единый `InstancedMesh` или `BatchedMesh` всего за **1 Draw Call** на GPU.
- **Frustum & Distance Culling:** Отсечение подписей, находящихся за пределами пирамиды видимости камеры или на расстоянии дальше порогового радиуса.
- **LOD (Level of Detail) & Decluttering:** При отдалении камеры подписи бутиков скрываются, остаются только якорные магазины (Фуд-корт, Супермаркет).

### 2. Обработка кликов при объединенной геометрии (InstancedMesh / BatchedMesh)
- **InstancedMesh Raycasting:** Стандартный Raycaster в Three.js при пересечении с `InstancedMesh` возвращает поле `intersection.instanceId`. По этому ID за $O(1)$ извлекаются данные из исходного массива объектов без декомпозиции геометрии.
- **GPU Color Picking (Offscreen Buffer):** Сцена рендерится в скрытый буфер 1×1 пиксель под курсором мыши, где цвет кодирует ID объекта (24 бита цвета дают до 16.7 млн ID). Метод `gl.readPixels` выполняется за $O(1)$ независимо от числа полигонов.

### 3. Структура хранения данных в JS для быстрого поиска по ID и координатам
- **Поиск по ID:** `Map<string, PlaceData>` — хэш-таблица обеспечивает мгновенный доступ со сложностью **$O(1)$**.
- **Поиск по координатам (X, Z):** **2D Spatial Hash Grid** (пространственная сетка). Плоскость разбивается на ячейки фиксированного размера. Координаты $(x, z)$ преобразуются в ключ ячейки математически за $O(1)$: `key = Math.floor(x/size) + ":" + Math.floor(z/size)`. Проверяются только 1–2 объекта в найденной ячейке вместо перебора всех 1000. Для сильно неравномерных площадей также эффективен **2D Quadtree** или **R-Tree (библиотека RBush)** со сложностью $O(\log N)$.
