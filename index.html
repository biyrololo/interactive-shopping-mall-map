📋 Архитектура и оптимизация (Раздел 4 ТЗ)

1. Оптимизация рендеринга текстовых подписей при 1000+ текстурированных объектах

В текущем прототипе для 100 объектов используются CSS2DRenderer (DOM-бейджи) и высокочеткие CanvasTexture. При масштабировании до 1000+ текстурированных объектов 1000 DOM-элементов вызовут перерасчет layout браузера (reflow/repaint). Для сохранения 60+ FPS применяются:

  • Distance & Frustum Culling: Скрытие подписей, находящихся вне пирамиды видимости камеры или на расстоянии дальше порогового радиуса.
  • SDF (Signed Distance Field) / MSDF Font Texture Atlas: Весь шрифт запекается в один атлас текстур (2048x2048). Все 1000 подписей отрисовываются через единый InstancedMesh (квады букв/строк) всего за 1 Draw Call.
  • LOD (Level of Detail) & Decluttering: При отдалении камеры отображаются только якорные магазины (Фуд-корт, Гипермаркет), мелкие бутики скрываются до приближения зума.
  • Shared 2D Canvas Overlay: Отрисовка всех видимых названий за один проход на прозрачный оверлей 2D canvas без тяжелых DOM-узлов.

2. Обработка кликов и Raycasting при объединенной геометрии (InstancedMesh / BatchedMesh)

  • InstancedMesh Raycasting: Стандартный Three.js Raycaster для InstancedMesh возвращает поле intersection.instanceId. Это позволяет мгновенно по индексу инстанса (instanceId) за \(O(1)\) достать метаданные магазина из массива данных без декомпозиции геометрии.
  • GPU Color Picking (Offscreen Buffer): Рендеринг сцены во внеэкранный буфер 1x1 пиксель под курсором с уникальным RGB-цветом для каждого ID (24 бита дают 16.7 млн уникальных ID). gl.readPixels выполняется за \(O(1)\) вне зависимости от 1,000 или 100,000 полигонов.
  • Spatial Index Pre-filtering (BVH / Grid): Луч луча тестируется не по всем объектам, а только по кандидатам из Spatial Hash Grid или Bounding Volume Hierarchy.

3. Структура хранения данных в JS для быстрого поиска по ID и координатам

  • Поиск по ID: Map<string, PlaceData> — обеспечивает мгновенный доступ со сложностью \(O(1)\).
  • Поиск по координатам (X, Z): Реализован Spatial Hash Grid (2D Grid Index) (см. src/data/spatialIndex.js). Плоскость этажа разбита на ячейки (бакеты). Координаты (x, z) преобразуются математически за \(O(1)\) в ключ ячейки cellX:cellZ, проверяются только 1-3 объекта-кандидата внутри ячейки. Для неравномерного распределения также эффективен 2D Quadtree или R-Tree (RBush) с поиском за \(O(\log N)\).

4. Описание алгоритма размещения без пересечений

Реализован Architectural Dual-Aisle Mall Gallery Packer (см. src/layout/packer.js):

  • Магазины группируются в галереи вдоль пешеходных проспектов (ширина прохода 4-5 м) с гарантированными зазорами между стенами.
  • Каждый объект имеет вычисленный AABB [minX, maxX, minZ, maxZ].
  • При загрузке автоматически запускается верификатор попарных коллизий (AABB Intersection Test), гарантирующий математическое отсутствие пересечений (\(0\) коллизий).
