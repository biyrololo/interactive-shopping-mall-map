Архитектура и оптимизация (Раздел 4 ТЗ)

1. Оптимизация текстовых подписей при 1000+ текстурированных объектах

При масштабировании до 1000+ объектов рендеринг 1000 отдельных DOM-элементов или тяжелых индивидуальных текстур вызовет падение FPS. Для поддержания стабильных 60 FPS применяются:

  • SDF (Signed Distance Field) / MSDF Font Atlas: Все глифы шрифта запекаются в один текстурный атлас. Все 1000 подписей отрисовываются как геометрические квады через единый InstancedMesh всего за 1 Draw Call на GPU.
  • Frustum & Distance Culling: Отсечение невидимого: на каждом кадре отключается рендер подписей вне пирамиды видимости камеры или дальше порогового расстояния.
  • LOD (Level of Detail) & Decluttering: При отдалении камеры отображаются только якорные магазины (Фуд-корт, Супермаркет). Подписи небольших магазинов проявляются только при приближении зума.

2. Обработка кликов по объектам при объединении геометрии (InstancedMesh / BatchedMesh)

  • InstancedMesh Raycasting: Стандартный Three.js Raycaster для InstancedMesh возвращает индекс инстанса intersection.instanceId. Это позволяет мгновенно по индексу за \(O(1)\) получить метаданные магазина из массива без разбиения геометрии на отдельные меши.
  • GPU Color Picking (Offscreen Framebuffer): Рендеринг сцены во внеэкранный буфер 1x1 пиксель прямо под курсором с уникальным RGB-цветом для каждого ID (24 бита цвета дают до 16.7 млн ID). Метод gl.readPixels считывает пиксель за \(O(1)\) вне зависимости от миллионов полигонов в сцене.

3. Структура хранения данных в JS для быстрого поиска по ID и координатам

  • Поиск по ID: Map<string, PlaceData> — встроенная хэш-таблица JS гарантирует доступ со сложностью \(O(1)\).
  • Поиск по координатам (X, Z): Spatial Hash Grid (2D Grid Index) или 2D Quadtree / R-Tree (RBush). Плоскость делится на сетку ячеек. Координаты мапятся в ключ ячейки математически за \(O(1)\), проверяя только 1-2 объекта в ячейке вместо перебора всех 1000.

4. Алгоритм размещения 100 объектов без пересечений

Использован алгоритм рядов торговых галерей с динамическим шагом (см. src/layout.js):

  • 100 магазинов упорядочиваются по рядам (по 10 магазинов в ряду).
  • По оси X магазины следуют с технологическим зазором 1.2 м.
  • По оси Z ряды разделены пешеходным проходом 3.5 м с учетом максимальной глубины ряда.
  • Автоматический тест checkCollisions гарантирует математическое отсутствие пересечений (0 коллизий).
